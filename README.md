# 长篇创作工作台

面向番茄小说长篇连载的 Windows 本地工作台。应用覆盖榜单研究、样本拆书、原创立项、300 万字滚动规划、逐章/五章批次写作、状态账本、质检、发布排期与数据复盘，并为每本作品建立独立数据库和检索索引。

应用不会登录番茄账号，也不会自动发布作品。所有发布动作均由作者在平台后台人工完成。

## 安装与启动

正式安装包位于：

```text
release\长篇创作工作台 Setup 0.1.0.exe
```

双击安装包，选择安装目录后完成安装。当前开发版没有商业代码签名证书，Windows SmartScreen 可能显示未知发布者；正式对外分发前应配置受信任的代码签名证书。

免安装构建位于：

```text
release\win-unpacked\长篇创作工作台.exe
```

## 首次配置

1. 打开“系统设置”。
2. 填写兼容 OpenAI Chat Completions 的 API 基础地址和模型名。
3. 填写输入、输出单价，用于批量任务执行前估算费用。
4. 保存 API 密钥。密钥存入 Windows Credential Manager，不写入 SQLite、日志、项目目录或备份包。
5. 在“多书总览”新建作品。每本书会立即建立独立目录、`project.sqlite`、FTS5 索引和语义向量表。

不配置 API 密钥时，榜单、导入、本地统计、规划、正文编辑、质检、排期、导出和备份仍可使用；语义拆书和 AI 写作不可用。

## 推荐工作流

1. 在“市场研究”采集无需登录的公开榜单页，或导入榜单 CSV。至少积累多个日期的快照后再判断趋势。
2. 导入有合法使用权的 TXT、EPUB、DOCX 或粘贴文本，检查切章预览后确认入库。
3. 选择仅本地分析，或明确同意本地脱敏后按十章批次调用云模型。系统生成章节、十章阶段、分卷、全书四级证据。
   拆解采用内置中国商业网文知识库，逐章提取进入期待、核心利益、主动行动、情绪回报、实际影响和下一期待；平台经验中的字数密度只作观察指标，不作为机械门禁。
4. 将脱敏洞察关联到新书，生成三个差异明显的候选方向。高原创风险候选必须人工复核。
5. 完成并审批创作契约，再建立宏观阶段、分卷、未来 30 章粗纲、未来 5 章细纲和当前章场景卡。
6. 在写作台保存章纲，预览编译后的最小上下文，再生成或手写正文。
   上下文会按题材和章节阶段加载商业写作任务，指导压力积累、回报兑现、影响发酵与下一轮追读，同时始终服从创作契约、人物动机和事实账本。
7. 常规章节可使用五章批次。执行前显示输入、输出和费用估算；关键章、卷界、重大状态变化、事实冲突或硬性告警会自动要求逐章处理。
8. 运行质检并处理硬性问题后人工确认定稿。质检始终执行离线规则；配置模型后会追加带正文或账本证据的语义审校。定稿会更新包含目标、结果、状态变化、未解决事项和章末推进的结构化摘要，并逐级汇总到十章阶段、分卷和全书。
9. 在状态账本维护人物、关系、能力、资源、地点、时间线、秘密、承诺、伏笔、支线和事件。
10. 安排待发布章节，导出 TXT、Markdown 或 DOCX 发布包及发布前检查报告，再人工发布。
11. 导入运营指标 CSV，查看周度相关性建议。指标不会自动修改创作契约、规划或正文。

## 人工门禁

- 创作契约未审批时不能批准规划或生成正文。
- 关键章、卷首卷末、重大状态变化、事实冲突和硬性告警强制逐章处理。
- 有未解决硬性问题的章节不能定稿或进入发布队列。
- 已审批创作契约、已批准规划、已定稿或发布中的章节如需修改，必须先批准改纲变更单；实际保存后变更单标记为“已应用”。
- AI 只生成候选、草稿和建议，不会自动定稿、改纲或发布。

## 研究隔离

- 原始样本只保存在 `research\research.sqlite`。
- 云端拆书仅发送本地脱敏后的分章片段，并需要逐本明确同意。
- 创作模型只接收脱敏洞察包，不接收研究原文。
- 原创门禁在研究库内比较哈希；作品质检记录只保存匿名研究引用和指纹，不复制样本书名或原句。
- 作者文风统计仅使用当前项目已定稿正文。

## 桌面安全边界

- Electron 渲染进程启用 sandbox、context isolation 和内容安全策略，不开放 Node.js 集成。
- IPC 只接受主窗口调用；项目、章节、导入、网络采集、模型设置和备份等写操作执行 Zod 运行时校验，并限制正文、CSV、URL、数组和密码规模。
- 榜单采集与模型地址只允许 HTTP/HTTPS 协议。参数错误只报告字段路径和规则，不回显 API 密钥、备份密码或完整正文。

## 数据位置

默认工作区：

```text
%USERPROFILE%\Documents\长篇创作工作台数据\
├─ catalog.sqlite
├─ research\research.sqlite
├─ projects\<作品ID>\project.sqlite
├─ projects\<作品ID>\attachments\
├─ projects\<作品ID>\exports\
└─ backups\
```

开发和自动化测试可通过 `NOVEL_STUDIO_WORKSPACE` 指定独立工作区。不同作品之间不会执行跨项目全文或向量检索。

## 备份与恢复

在“系统设置”输入至少 8 位密码后创建 `.novelbak`。备份采用 AES-256-GCM 加密，包含数据库、作品目录、附件及文件清单；创建前会执行 SQLite checkpoint。

恢复操作先解密并校验完整清单，再写入新的恢复副本目录，不覆盖正在使用的工作区。备份密码不会保存，API 密钥也不会进入备份包。

## 可靠性与任务审计

- 章节、期待账本、历史版本、全文索引和向量索引在同一事务中保存；自动保存失败会保留本地恢复稿并重试。
- 健康检查在后台线程运行，可查看进度和取消；索引修复始终由用户显式触发。
- AI 任务中心记录状态、模型、真实 Token、费用与耗时；应用异常退出后的运行中任务会标记为已中断。
- 每次 AI 调用保留独立审计记录；正文任务可在任务中心取消或安全重试，五章批次会跳过已有正文，只补齐未成功章节。
- AI 取消覆盖请求与服务退避等待。供应商不支持 JSON mode 时会自动降级到提示词约束 JSON。
- 提示词版本绑定正文、事实提取和质检回归语料，结构、事实、重复与成本评分低于基线时测试失败。
- 本地恢复稿无法写入时，编辑器会明确显示“恢复副本不可用”。

自动备份可按每日或每周执行，并保留最近 1–30 份。自动备份专用密码仅存入 Windows Credential Manager，不写入 SQLite、日志或备份文件；关闭自动备份时会删除该凭据。自动生成的备份保存在工作区 `backups` 目录，轮换只处理以 `auto-` 命名的系统备份，不删除手动创建的 `.novelbak`。失败任务会记录脱敏错误并在一小时后重试。

“系统健康”可手动检查目录库、研究库及每本作品库的 SQLite 完整性，核对章节记录与两套 FTS 索引数量，报告孤立项目目录、失败 AI 任务和磁盘占用。搜索索引不一致时可以从章节正文记录事务化重建；数据库损坏、缺失项目文件和孤立目录只报告，不会自动删除、移动或覆盖数据。

## CSV 字段

榜单 CSV 支持：

```text
排名,书名,作者,题材,字数,状态,标签,链接
```

运营指标 CSV 支持中英文字段名，常用列为：

```text
日期,章节,曝光,阅读,留存,追读,收益,评论摘要
```

留存可使用数字或百分号格式。分析只报告时间相关性，不将波动表述为确定因果。

## 本地开发

建议使用 Node.js 22 LTS、Windows 10/11 和 SSD：

```powershell
npm ci
npm run dev
```

常用命令：

```powershell
npm test                 # 单元与隔离测试
npm run test:quality     # 提示词结构与小说质量固定基准
npm run test:scale       # 10 本书 × 1500 章 × 300 万字容量测试
npm run test:e2e         # 浏览器桌面/移动端交互测试
npm run build            # React 与 Electron 生产构建
npm run test:electron    # 源码生产构建及打包应用冒烟测试
npm run dist:win         # 生成 Windows NSIS 安装包
```

公开榜单采集只访问用户提供的无需登录 HTTP/HTTPS 页面，不携带 Cookie、不绕过访问限制。页面无法稳定访问时应改用 CSV 或人工录入。

## P2 工程保障

- 项目页按规划、写作、状态账本、质检、发布拆为独立工作区；章节生命周期和审批版本门禁由 `src/shared/chapter-lifecycle.ts` 在浏览器与桌面端共享。
- Electron 数据层由项目、研究、修订、搜索、AI 审计五类仓储组成，`WorkspaceDatabase` 保留兼容门面。
- 写作台对章节列表使用虚拟窗口，首次增量加载 200 章；全文检索每页 50 条，并在滚动到底部后继续加载。
- AI 审计默认保留 90 天且最多 5000 条；健康任务保留 24 小时且最多 100 条完成记录。
- 桌面日志为 JSON Lines，写盘前脱敏密钥、Bearer、URL 凭据和 Windows 用户目录。系统设置可导出不含正文和数据库的诊断 ZIP。
- 自动更新只在打包应用中启用。安装前必须成功创建加密的 `pre-update-<version>.novelbak` 数据快照；安装器失败时保留当前版本。数据恢复仍需通过“校验并恢复副本”人工确认，避免自动覆盖唯一工作区。

Windows 发布流水线需要配置 `WINDOWS_CERTIFICATE_BASE64`、`WINDOWS_CERTIFICATE_PASSWORD` 和 `WINDOWS_PUBLISHER_NAME` 三个 GitHub Secrets。标签 `v*` 触发测试、构建、签名、GitHub Release 和 `latest.yml` 更新通道发布。

## 质量评测基准

`src/shared/quality-benchmark-corpus.ts` 保存与提示词版本绑定的固定案例。首批案例覆盖角色知识边界、资源守恒、时间地点冲突、连续回报机制重复和正常章节误报控制。每个预期问题都声明类别、严重级别、匹配语义和可追溯证据。

`npm run test:quality` 分别计算问题召回率、准确率、严重级别准确率、证据准确率和误报控制率。硬性问题漏检、证据不在正文或上下文中、命中禁止误报，都会直接判定失败；Token 成本继续由提示词结构基准单列衡量，不与质量分互相抵消。修改质检提示词或模型版本前，应先增加能复现目标问题的案例，再比较候选输出与当前基线。

写作台的“预览上下文”会说明每类材料的来源、入选原因、入选/候选数量、字符占用和截断状态，并提示未审批契约、缺失卷纲、账本冲突或事实不足。诊断元数据不会发送给模型，也不计入输入 Token。

正文生成前会运行确定性状态约束：未解决账本冲突、同一有效区间的多值事实和明确的数字资源超支会阻止单章及五章批次生成；涉及受限秘密只提示知情范围，不凭自然语言猜测角色行为。历史版本支持段落级增删对比，质检中心按章节汇总待质检草稿与未处理问题。

数据复盘可建立运营实验，分别记录假设、计划改动、影响章节、基线期、观察期、主指标、成功标准和干扰因素。实验结束时必须填写结论并选择保留、撤销或继续观察；实验记录不会自动修改正文、契约或章纲，剧情调整仍需通过变更单。

故障注入仅在 `NODE_ENV=test` 生效，可通过 `NOVEL_STUDIO_FAULTS` 启用 `disk-full`、`power-loss-before-commit` 或 `credential-unavailable`。测试还会写入真实损坏的 SQLite 文件验证健康诊断不中断。
